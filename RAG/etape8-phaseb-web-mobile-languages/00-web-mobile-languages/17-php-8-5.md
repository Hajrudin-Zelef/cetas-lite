# 17. PHP 8.5

## 17. PHP 8.5

- PHP 8.5 released 2025-11-20 according to several secondary sources [secondary].
- Pipe operator `|>`: chains callables left-to-right (use the accepted callable form; some blog snippets show incorrect syntax — do not reproduce `$$`-style examples) [secondary].
- URI extension: new URI API supporting RFC 3986 and WHATWG URL models [secondary].
- Clone-with changes (immutable-style modification on clone) [secondary].
- `#[NoDiscard]` attribute [secondary].
- `array_first()` / `array_last()` functions [secondary].
- Callable and constant-expression evaluation changes [secondary].
- Sources: https://laravelmagazine.com/php-85-is-here-the-pipe-operator-uri-extension-and-more, https://laravel-news.com/the-pipe-operator-is-coming-to-php-85, https://github.com/hoceineel/personal-portfolio/blob/HEAD/content/blog/php-85-complete-guide.md [secondary].

## 18. Ruby 4.0 — ZJIT, Ruby Box, Ractor

### 18.1 Release

- Ruby 4.0.0 was released on **2025-12-25** (Christmas Day, per the project's tradition) [secondary]; the official announcement is at https://www.ruby-lang.org/en/news/2025/12/25/ruby-4-0-0-released/ (observed via the www.ruby-lang.org repo mirror: https://github.com/ruby/www.ruby-lang.org/blob/HEAD/en/news/_posts/2025-12-25-ruby-4-0-0-released.md) [secondary].
- Previews: 4.0.0-preview3 on 2025-12-18; preview2 around 2025-11-17 [secondary].
- Note: an earlier `v3_5_0_preview1` NEWS.md existed in the ruby/ruby repo, but the Prism changelog records the version rename from 3.5 to 4.0 ("Rename version 3.5 to version 4.0", "Support 4.1 as a version option", "Ruby 4.0.2 maintenance release") [secondary]. ⚠️ Do not describe Ruby 3.5 as a released version; the line became 4.0.
- Sources: https://github.com/ruby/ruby/blob/v3_5_0_preview1/NEWS.md, https://github.com/ruby/prism/blob/HEAD/CHANGELOG.md [secondary].

### 18.2 ZJIT — the new method-based JIT

- ZJIT is a new experimental method-based JIT compiler merged into Ruby (announced May 2025), compared with YJIT's lazy basic-block versioning approach; the more traditional architecture is intended to be more accessible to new contributors [secondary].
- Enable at runtime with `--zjit` or `RubyVM::ZJIT.enable`; building Ruby with ZJIT support requires Rust 1.85.0 or later [secondary].
- As of Ruby 4.0.0, ZJIT is faster than the interpreter but not yet as fast as YJIT — experimentation is encouraged, production deployment is not advised [secondary].
- Stated goal: make ZJIT faster than YJIT and production-ready in Ruby 4.1 [secondary].
- YJIT changes in 4.0: `ratio_in_yjit` no longer works in the default build (use `--enable-yjit=stats` at configure time); `invalidate_everything` added to default stats; `mem_size:` and `call_threshold:` options added to `RubyVM::YJIT.enable` [secondary].
- `--rjit` was removed; the third-party JIT API implementation moves to the `ruby/rjit` repository [secondary].
- Source: https://www.infoworld.com/article/4113436/ruby-4-0-0-introduces-zjit-compiler-ruby-box-isolation.html [secondary].

### 18.3 Ruby Box — experimental in-process isolation

- Ruby Box is an experimental capability for in-process separation of classes and modules — isolated "boxes" within one Ruby process for code, libraries, and monkey patches [secondary].
- Anticipated use cases: running test cases in a box to protect other tests from monkey patches, parallel web-app boxes for blue-green deployments in one process, evaluating dependency updates by diffing responses [secondary].
- Enable with `RUBY_BOX=1`; exposes `Ruby::Box` (constants also visible under the new top-level `Ruby` module: `Ruby::VERSION`, `Ruby::DESCRIPTION`, `Ruby::Box`, etc.) [secondary].
- Experimental with known issues [secondary].

### 18.4 Ractor and performance

- `Ractor::Port`: new class addressing message send/receive issues [secondary].
- `Ractor.shareable_proc`: makes it easier to share `Proc` objects between Ractors [secondary].
- Internal data structures improved to reduce contention on global locks: frozen strings and the symbol table use a lock-free hash set; method-cache lookups, class/generic-ivar access, and `object_id` avoid locking in most cases; per-Ractor allocation counters and thread-local xmalloc/xfree counters avoid CPU cache contention [secondary].
- Bug fixes: deadlocks combining Ractors and Threads, `require`/`autoload` in Ractors, encoding/transcoding across Ractors, GC race conditions, fork-after-Ractor issues, accurate GC allocation counts under Ractors, TracePoints after GC [secondary].
- Other 4.0 items: `Set` and `Pathname` promoted to core; logical operators (`and`/`or`/`&&`/`||`) allowed at the start of the next line; clearer error messages; refinements across IO, Fiber, Thread, Enumerator [secondary].
- Sources: https://github.com/nithinbekal/nithinbekal.github.io/blob/HEAD/_posts/2025-12-17-ruby-4-0.md, https://medium.com/@bhagawatadhikari94/ruby-4-0-0-is-here-a-big-step-toward-safer-faster-and-more-parallel-ruby-367cedbf0c4a [secondary].
