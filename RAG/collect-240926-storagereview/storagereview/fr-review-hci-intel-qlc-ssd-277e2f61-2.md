# fr-review-hci-intel-qlc-ssd-277e2f61

In the IT industry, there is often a tendency to marvel at demonstration machines – the fastest and/or most powerful devices or systems – because we love the impressive numbers they display. However, the reality is that most users simply do not need that ostentatious power. They need robust systems, capable of handling real-world workloads on a daily basis, at an affordable price. We have spent a lot of time studying DataON's hyperconverged infrastructure (HCI) solutions, and we even awarded the DataON HCI-224 equipped with Intel® Optane™ SSDs our "Editor's Choice" award last year. In this article, we will examine another two-node HCI-224 cluster. This one features a unique storage combination: an Intel Optane™ SSD in front and a 15.36 TB Intel® D5-P4326 SSD with 3D QLC NAND memory, creating a system that optimizes capacity, performance, and cost.
Before delving into this cluster in detail, we will first explain why DataON opted for QLC as the capacity storage tier, and present an overview of Microsoft Azure Stack HCI, DataON, and two-node HCI clusters.
Intel® D5-P4326 Series SSD
The use of the QLC-based Intel D5-P4326 SSD for capacity storage in this HCI cluster is a logical choice, as it offers solid, reliable, and economical performance. We have certainly seen faster SSDs, but the D5-P4326 SSD finds the right balance between performance and cost, with a massive capacity of 15.36 TB per drive. This combination is due to its underlying architecture. Thanks to Intel® QLC 3D NAND technology, Intel is able to reduce the cost of this device while increasing its capacity.
Intel was one of the first storage vendors to manufacture QLC-based drives. QLC technology, or quad-level cell, stores four bits of data on a single cell, while older technologies such as TLC, MLC, and SLC store only three, two, or one bit(s) per cell. Thanks to higher-density QLC storage, they can have a lower cost per GB of storage. In addition, Intel's 3D NAND technology allows these cells to be stacked horizontally on the chip, further increasing storage density. There is a trade-off, however. To effectively leverage the Intel SSD D5-P4326 SSD, write workloads must be buffered before entering the QLC-based drive. QLC SSDs are perfectly suited for capacity-optimized and read-intensive workloads. Thus, platforms such as an HCI cluster must use an appropriate cache device in front of the QLC SSDs to deliver consistent performance. In the case of the DataON HCI-224, four 750 GB 2.5-inch Intel Optane DC P4800X NVMe SSDs are used per node to absorb writes before moving data to the QLC tier. This approach prevents excessive writes from causing performance degradation of the QLC tier. The net result is that customers benefit from a seamless experience and an ideal blend of Intel Optane-based performance with QLC-based capacity.
Microsoft Azure Stack HCI
In short, Microsoft Azure Stack HCI is an on-premises implementation of Microsoft Azure Cloud Services. Essentially, Microsoft integrated its existing HCI technology into the Azure Stack family so that its customers can run virtualized applications on-premises with direct access to Azure management services such as backup and disaster recovery.
Azure Stack HCI should not be confused with Azure or Azure Stack Hub. While Azure is a public cloud service, Azure Stack Hub and Azure Stack HCI are on-premises solutions. Additionally, Azure Stack Hub runs Azure OS with Azure Services and is an IaaS and PaaS solution. Azure Stack HCI, on the other hand, runs the Windows Server operating system with Azure Services and allows you to run virtualized workloads in the same way you are accustomed to, with the added benefit of being able to connect to the Azure cloud for additional services. This is a huge difference that allows IT administrators to use the same tools and management stack on Azure Stack HCI that they use with Azure.
Azure Stack HCI uses Hyper-V for its hypervisor, Storage Spaces Direct for storage, Microsoft Software Defined Networking (SDN) for networking, and Windows Admin Center (WAC) for its management. Azure Stack HCI runs on standard x86 servers and other basic components.
WAC is a browser-based management platform deployed locally that can manage both on-premises and Azure cloud-based instances of Windows 10 and Windows Server. WAC is installed on a Windows system and uses PowerShell scripts. It also uses Microsoft Windows Management Framework (WMF) over WinRM (Windows Remote Management) to monitor and manage Windows systems, including HCI clusters and Azure virtual machines.
WAC's main dashboard provides an overview of CPU, memory, network, and disk activity for monitored systems. On the left side of the screen, WAC also includes a number of management and system navigation tools, including certificates, devices, events, files, local users and groups, firewall, processes, registry, roles and features, services, and storage.
DataON was one of the first companies to leverage WAC's open framework and ported its Management Utility Software Tool (MUST) extension to WAC. DataON MUST provides visibility, monitoring, and infrastructure management for HCI, networking, and storage based on a Windows Server.
DataON HCI
Although Azure Stack HCI uses standard hardware components, these elements must be designed to work together and deliver optimal performance. In some ways, it is simpler to design high-performance systems than robust systems. With high-performance systems, it is possible to select the best components and disregard cost. In contrast, for robust systems, it is necessary to evaluate the cost/performance ratio of components and then optimize them. Building a value-focused system requires an engineering effort that is just as significant, if not greater, and it is precisely in this area that DataON continues to impress us.
DataON has a strong partnership with Microsoft and Intel, and they have capitalized on these relationships when designing systems for Azure Stack HCI. DataON's Intel Select HCI solutions can be preconfigured and shipped in their own rack, ready to be deployed immediately. This delivery method is not only useful in the data center but also proves beneficial for systems deployed at the edge where existing IT infrastructure and personnel are either limited or nonexistent.
2-Node HCI Clusters
We recently published an article on Microsoft Azure Stack HCI two-node clusters (2NC). Below is a summary of that article. We found that a 2NC cluster can, in many use cases, provide the resilience an organization needs and is less complex and less expensive than a traditional three- or four-node cluster. DataON was among the first vendors to recognize the value of 2NC clusters and adopt their integration. However, 2NC clusters are not new to DataON: in September 2017, the company announced the commercialization of the first two Kepler-47 HCI systems for Windows Server 2016 Storage Spaces Direct (now Azure Stack HCI).
DataON's 2NC implementation supports a disk failure and a server failure at the same time. To do this, it uses RAID 5 + 1 to ensure parity resilience and mirror it to the other server. Microsoft calls this capability "nested resiliency" and added this capability to Storage Spaces Direct in Windows Server 2019. Again, 2NC is not the right technology choice for everyone, but they can provide a reliable and cost-effective solution for many organizations.
