# 1. C

## 1. C

### 1.1 Standards: C17, C23, C2y

- The current published ISO C standard at the cutoff is **ISO/IEC 9899:2024 (C23)**, published October 2024. [secondary]
- C23 changes reported in secondary sources include `_BitInt` extended-width integers, `nullptr` (via `<stddef.h>`), `constexpr`, `typeof`/`typeof_unqual`, `static_assert` as a keyword, and `bool`/`true`/`false` as keywords. [secondary]
- WG14 work on the next revision (informally "C2y") was in progress during 2026, but no ratified new standard existed at the cutoff. [unverified]
- The task brief framed C in terms of C23 only; treat any C2y feature claims as working drafts, not standards. [unverified]

### 1.2 Compilers and toolchains

- **GCC 16.1** was released **2026-04-30** as the first GCC 16 series release; **GCC 16.2** followed on **2026-08-07**. [official]
  - GCC 16 changes its default C++ standard from C++17 to GNU C++20 and ships experimental support for C++26 features including reflection, contracts, expansion statements, constexpr exceptions, `std::simd`, `std::inplace_vector`, `optional<T&>`, `copyable_function`, and `function_ref`. [secondary]
  - For C, GCC 16 extends `_BitInt` support to RISC-V, ARM, S390 and LoongArch; adds a new experimental Algol 68 frontend (`ga68`); introduces SARIF and HTML diagnostic formats. [secondary]
  - New target support includes LoongArch32; tuning updates cover Zen6, Wildcat Lake and Nova Lake. [secondary]
  - Sources: https://linuxiac.com/gcc-16-1-released-as-first-gcc-16-series-release-with-c20-default/ , https://github.com/tamnd/rucc/blob/HEAD/spec/cross-compile/01-research-2026.md
- **Clang 21/22**: Phoronix testing in September 2026 compared GCC 15.2, GCC 16.1, and Clang 21.1.4 on an AMD Threadripper 9980X with Fedora 44 and `-O3 -march=native`, reporting faster generated binaries from GCC 16. Do not generalize beyond that exact setup. [independent]
  - Source: https://www.phoronix.com/review/gcc-16-vs-clang-22
- **MSVC**: no new Microsoft C/C++ toolchain release notes were corroborated during this research; MSVC conformance updates through Visual Studio 2022 17.x continued but exact 2026 claims are a gap. [unverified]
- **Fedora Workstation 44** (released circa September 2026) ships GCC 16 as the default compiler, per secondary reporting. [secondary]

### 1.3 Memory-safety story

- C provides no memory safety by construction: manual memory management, raw pointers, and undefined behavior on misuse. [secondary]
- Mitigations used in production C codebases include: sanitizers (AddressSanitizer, UBSan), fuzzing, static analysis, compiler hardening flags, bounds-aware abstractions, FFI isolation, and capability-hardware approaches such as CHERI research. None of these make arbitrary C memory-safe. [secondary]
- Policy pressure (CISA/NSA guidance, EU Cyber Resilience Act, German BSI NIS-2 guidance) increasingly pushes new high-risk code toward memory-safe languages, with incremental migration of legacy C/C++ components. [secondary]
  - The CISA Secure by Design pledge reportedly had 296+ organizations signed by late 2025, with memory-safety roadmaps due around 2026-01-01. [secondary]
  - EU CRA reporting obligations began September 2026; main product obligations apply from December 2027. [secondary]

### 1.4 Ecosystem position at the cutoff

- C ranked **#2** on the TIOBE index for September 2026 at **10.28%**, behind Python. [independent]
- C remains the implementation language of operating-system kernels, embedded firmware, and runtimes of other languages in this file. [secondary]
- C ABI remains the lingua franca for foreign function interfaces: Rust, Zig, Go (cgo), Julia (ccall), Mojo, and V all interoperate with C. [secondary]

## 2. C++

### 2.1 C++26 status

- WG21 approved/finalized the C++26 draft on **2026-03-28**; distinguish the committee's final draft ballot from final ISO publication when wording "C++26 released" claims. [secondary]
- Central C++26 topics: **contracts**, **reflection** (P2996-style static reflection), and substantial standard-library additions (`std::simd`, `std::inplace_vector`, `optional<T&>`, `copyable_function`, `function_ref`). [secondary]
- Contracts were contentious: press coverage in March–April 2026 noted they entered the draft "despite disagreement over their value". [independent]
  - Sources: https://en.wikipedia.org/wiki/C++26 , https://www.theregister.com/software/2026/03/31/contracts-are-in-c26-despite-disagreement-over-their-value/5229065 , https://www.devclass.com/development/2026/04/01/contracts-are-in-c26-despite-disquiet-over-their-value/5213555
- C++26 does **not** make C++ memory-safe by default; treat any claim that C++26 provides broad "memory-safety guarantees" as uncorroborated. [unverified]
- Memory-safety-adjacent work in the C++ ecosystem (profiles, bounds-safety annotations, hardened standard libraries, Safe C++ proposals) remains a mix of proposals and vendor extensions at the cutoff, not a single standardized safe subset. [secondary]

### 2.2 Compilers

- **GCC 16** (16.1 on 2026-04-30, 16.2 on 2026-08-07) defaults to GNU C++20 and carries experimental C++26 reflection/contracts/constexpr-exception support plus experimental named modules. [secondary]
- **Clang**: the 21.1.4/22 series was current in September 2026; Phoronix measured GCC 16 producing faster binaries than Clang 21.1.4 in its Threadripper 9980X / Fedora 44 / `-O3 -march=native` test set. This is one lab's result, not a general verdict. [independent]
- **MSVC**: Microsoft's compiler continued to track C++20/C++23 conformance via Visual Studio updates; no 2026-specific MSVC version claim was corroborated. [unverified]
- Intel's compiler line (classic icc retired; oneAPI DPC++/C++ Compiler based on Clang) was not re-verified at the cutoff. [unverified]

### 2.3 Build systems and packaging

- **CMake** was in the **4.x** generation at the cutoff: CMake 4.0 removed compatibility with versions older than 3.5; **CMake 4.3** added Common Package Specification (CPS) support (`find_package` importing CPS packages, `install(PACKAGE_INFO)`, `COMPAT_VERSION`/`SPDX_LICENSE` project options) and a new instrumentation API; **CMake 4.4** was in development with diagnostics-state management (`cmake_diagnostic`) and presets schema v12. [official]
  - Sources: https://github.com/kitware/cmake/blob/HEAD/Help/release/4.3.rst , https://github.com/x-ecutionner/cmake/blob/HEAD/Help/release/4.4.rst
- **Meson**: 1.10.1 was the default built version in Bazel's rules_foreign_cc (September 2026), reflecting its current line. [secondary]
- **Bazel**: 8.6.0 was the primary tested version for bzlmod; Bazel 7 remained supported in WORKSPACE mode only. [secondary]
- **Ninja** 1.13.2 and **GNU Make** 4.4.1 were the current lines referenced in September 2026 toolchain metadata. [secondary]
- **vcpkg / Conan**: the two main C++ package managers; neither had a 2026 headline feature corroborated during this research. [unverified]
- C++ modules (named modules, BMI distribution) remained a slow-burn adoption story: supported experimentally by GCC 16 and other compilers, with build-system support still maturing at the cutoff. [secondary]

### 2.4 Ecosystem position

- C++ ranked **#3** on TIOBE September 2026 at **8.67%**. [independent]
- Domains where C++ remained dominant at the cutoff: game engines, browsers, HPC, quantitative finance, embedded performance-critical code, and large legacy codebases. [secondary]
- Carbon (Section 6) is Google's experimental effort at a C++ successor with bidirectional interoperability; it remained pre-release. [secondary]
